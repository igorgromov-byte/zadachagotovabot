# Design Audit Bot — первая версия

Telegram-бот для проверки сдачи дизайн-задач в Asana и Google Drive.
Код подготовлен и проверен локально. Для запуска нужны отдельные учетные данные;
подключения Asana/Drive в ChatGPT не передаются этому приложению.

## Что делает

- Следит за пятью согласованными бордами. Условие закрытия: `completed=true`
  **и** раздел «Готово» именно в соответствующем борде.
- При первом успешном чтении каждого борда фиксирует уже закрытые задачи и
  исключает их из автоматического контроля. Начальное чтение служит границей запуска.
- Каждые 3 минуты проверяет изменения. Первую проверку запускает через
  20 минут после того, как увидел оба условия закрытия. Порядок галочки и переноса
  не важен, в том числе если галочку поставили до запуска, а перенесли после.
- Читает все страницы комментариев, берет размеченные ссылки сдачи,
  рекурсивно обходит папки. Несколько папок и одна общая папка допустимы.
  Один и тот же ID файла считается один раз; разные ID с одним именем — ошибка.
- Проверяет нейминг, гео/оффер, комплект размеров по уникальным именам,
  эндкарты и пары playable HTML + MP4, наличие проекта, фактическую иерархию.
- Сверяет название с фактическими размерами, если Drive вернул медиа-метаданные.
  Если их нет, явно пишет, что размер не проверен.
- Отправляет ошибки и вопросы в настроенный Telegram-чат. После исправлений:
  кнопка «Перепроверить» или `/check ССЫЛКА`.
- Перепроверяет новые закрытые задачи раз в час в течение 7 дней; неизменный
  отчет повторно не отправляет. Результаты и очередь хранятся в SQLite.
- Работает с Asana и Drive только на чтение. Telegram принимает команды
  только от заданного владельца и только из заданного чата.

## Важные границы первой версии

Это формальная проверка сдачи, а не оценка содержания рекламного креатива.
Свободный текст пока разбирается правилами, без внешней языковой модели:
распознаются формулировки «2 версии», «2 видео», «в 2 стилях», а также
«два/две/три/четыре/пять». Повтор одного требования не умножает число версий.
Противоречия и смысл ТЗ направляются на ручную сверку. Если явного количества
нет, для первичной проверки предполагается одна версия; это не подтверждение
полноты ТЗ. Число уникальных имен не доказывает наличие нужных сюжетов.

ZIP/RAR не распаковываются. Открытие проекта, комплект исходников, шрифты,
плагины, качество ролика и содержание эндкарт не проверяются. При наличии
архива отчет всегда содержит это ограничение. Один общий проект нескольких
версий возможен, но его связь с вариантами требует сверки.

Для нескольких версий проверяется наличие эндкарт заданных размеров на гео,
а распределение общих/индивидуальных эндкарт выводится на ручную сверку.
Поле эндкарты определяет отдельные изображения; слова «пэкшот»/«end card»
в сценарии сами по себе не добавляют требование отдельного файла.

Поддерживается стандартная подпись формы в комментариях:

```text
Ссылки на файлы:
https://drive.google.com/drive/folders/...
https://drive.google.com/drive/folders/...

Проект:
https://drive.google.com/drive/folders/...
```

Ссылки без подписи требуют классификации вручную, чтобы бот не принял
референс за финальную сдачу. При нескольких сдачах берется объединение
размеченных ссылок: устаревшие версии могут дать лишние файлы/дубли;
автоматического определения «последнего аппрува» пока нет.

## Нейминг

| Тип | Шаблон | Тегов |
|---|---|---:|
| Общий креатив | `OLNE_Delimobil_RU_220825_video_roulettev2_1920_1080.mp4` | 8 |
| Общий проект | `OLNE_Delimobil_RU_220825_collect_roulettev2.zip` | 6 |
| Winline креатив | `WINLINE_060426_IOS_video_Ronaldo_1080x1920_RU_POCH.mp4` | 8 |
| Winline проект | `WINLINE_210826_IOS_collect_Slots_1080x1920_BY_POCH.zip` | 8 |

Подчеркивание — разделитель тегов. `roulette_v2` и `UGC_cafe` недопустимы;
нужно `roulettev2` и `UGCcafe`. Форматы общего стандарта: video/static/playable,
у Winline: video/banner/playable. Проекты: collect. У Winline всегда IOS,
размер сохраняется в проекте, гео RU/BY/KZ. Проверяется календарная дата ДДММГГ.
Сопоставление оффера с полем Asana нечувствительно к регистру.
Справочник инициалов в config.json предварительный, неизвестные — на сверку.
Инициалы файла не приравниваются к исполнителю задачи: авторов может быть несколько.

## Карта папок

В `config.json` уже записаны подтвержденные ID пяти бордов и разделов «Готово».
Корни проверяются по ID, а не по одинаковым названиям папок.

| Борд | Корень креативов | Корень проектов |
|---|---|---|
| Design / RockApp, NATIVE | общий NATIVE | общий Ae_Projects |
| Design - Summon Web | общий Buying Web Summon | общий Ae_Projects |
| Anastasiia Kilchynska | Buying Web Summon внутри персональной папки | AE_projects там же |
| Semen Smirnov | Buying Web Summon внутри персональной папки | еще не подтвержден |
| Ovannes Aleksanian | еще не подтвержден внутри персональной папки | еще не подтвержден |

Для незаполненных корней бот ищет ровно одну дочернюю папку с ожидаемым
именем **внутри подтвержденной персональной папки**. Если ее нет или их
несколько, не придумывает ID и сообщает, что маршрут не настроен.
После появления новой корректной сдачи закрепите найденные ID в config.json.
Старые ошибочные пути не внесены в исключения. Другие департаменты RockApp
пока требуют отдельного подтверждения маршрута.

После корня креативов ожидается `оффер → гео → год → папка сдачи`.
Гео может быть общим набором, например `KG, TJ, UZ`. Далее разрешены вложенные
папки. После корня проектов — `инициалы → оффер → папка проекта`.
Точная структура **имени папки сдачи** не навязывается: у общих и раздельных
сдач она различается. Название папки проекта сверяется с именем файла проекта;
несовпадение выводится на ручную сверку.

## Что нужно от владельца для запуска

1. Постоянно работающий сервер с Docker Compose и исходящим HTTPS-доступом
   к Asana, Google APIs и Telegram. Открывать входящий порт не требуется.
2. Токен Asana учетной записи с доступом к пяти бордам. Создать в настройках
   разработчика Asana. Для production лучше выделенная учетная запись.
3. Google Cloud project с включенным Drive API и учетные данные с правом
   читать рабочие папки. Поддерживаются стандартные Google Application Default
   Credentials: сервисная учетная запись либо authorized_user с refresh token.
   Для сервисной учетной записи предоставьте ее email доступ к нужным папкам
   или общему диску; учитывайте ограничения организации. Публичные ссылки не нужны.
4. Бот Telegram, созданный через официальный @BotFather командой `/newbot`.
   Владелец должен открыть бота и нажать Start. Нужны токен, ID владельца и ID чата.
   Для личной переписки ID чата и пользователя обычно совпадают. Получить их
   можно локально через getUpdates после Start; не публикуйте токен в URL чата.

Секреты записываются в `.env` и `secrets/google.json` на сервере.
Не вставляйте токены в Asana, Google Docs или общие чаты.

## Запуск на сервере

Распакуйте архив и откройте терминал в каталоге design-audit-bot:

```bash
cp .env.example .env
mkdir -p secrets data
```

Заполните `.env`; положите Google credentials в `secrets/google.json`.
Файл должен быть действительным JSON учетных данных, а не просто API key.

```bash
docker compose build
docker compose run --rm bot python app.py doctor
```

`doctor` проверяет доступ к бордам/разделам, корневым папкам и getMe Telegram.
Ничего не пишет в Asana/Drive и не отправляет сообщений. `НЕ НАСТРОЕНО`
означает, что соответствующая проверка маршрута пока будет только предупреждением.
Для ручной проверки одной задачи с JSON-отчетом в терминале:

```bash
docker compose run --rm bot python app.py check 1217953590115558
```

После проверки подключения:

```bash
docker compose up -d
docker compose logs --tail=50 bot
```

В Telegram отправьте `/status`. Для ручного отчета — `/check` и ссылку Asana.
Чтобы остановить: `docker compose down`.
После изменения config.json: `docker compose restart bot`.

Не запускайте два экземпляра с одним токеном Telegram/одной базой данных.
Каталог `data` должен сохраняться при перезапусках. Его удаление заново
задаст границу автоматического контроля. Сохраняйте резервную копию базы
при остановленном боте. Отправка Telegram и запись SQLite не являются общей
транзакцией: при аварии ровно между ними возможен повтор последнего отчета.
При полном цикле «открыть → закрыть» между двумя опросами бот может не увидеть
промежуточное состояние; для таких случаев есть ручная перепроверка.

## Подтвержденные требования для нестандартных задач

В `task_overrides` можно задать проверенный состав результата по ID задачи:

```json
{
  "1210000000000000": {
    "sizes": [[1080, 1920], [1920, 1080]],
    "geos": ["BY"],
    "versions": 2,
    "variant_names": ["AnimationCasino", "AnimationSport"],
    "kind": "video",
    "endcards": [[800, 800]],
    "project_required": true,
    "semantic_confirmed": true,
    "notes": []
  }
}
```

`project_required: false` ставится только для подтвержденного исключения.
После изменения ТЗ обновите override; он не обновляется сам и имеет приоритет
над распознаванием текста. Реальные старые задачи в overrides не добавлены.

## Проверка кода

Python 3.12:

```bash
python -m venv .venv
. .venv/bin/activate
pip install -r requirements.txt
python -m unittest discover -s tests -v
```

Тесты проверяют правила на искусственных данных и сетевое взаимодействие
через подставные ответы. Это не проверка production-авторизации и не запуск
боевой рассылки. Локальные подключения бота требуют отдельного `doctor`.
